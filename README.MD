# Этапы 1–3. Конфигурация, сбор данных и построение графа

CLI-приложение на стандартной библиотеке Python загружает настройки из INI,
получает информацию о пакете в формате Alpine APK, рекурсивно строит
достижимый граф его зависимостей обходом DFS и выводит рёбра графа.
Визуализация графа будет добавлена на следующих этапах.

## Настройка

Параметры задаются в секции `[settings]` файла `config.ini`:

| Ключ | Назначение и проверка |
| --- | --- |
| `package_name` | Имя пакета; обязательное, без пробелов. |
| `repository` | При `test_mode = false` — полный HTTP(S) URL с хостом; при `true` — путь к существующему файлу тестового репозитория. |
| `test_mode` | Режим тестового репозитория: только `true` или `false`. |
| `version` | Версия пакета; обязательная, без пробелов. |
| `output_file` | Имя файла изображения; поддерживаются расширения `.png` и `.svg`, путь к каталогу указывать нельзя. |

Пример готовой конфигурации находится в `config.ini`.

## Запуск

Запустить из корня проекта:

```sh
./run.sh
```

Скрипт запускает приложение с `python3` из корня проекта, поэтому его можно
вызвать и из другого текущего каталога.

По умолчанию читается `config.ini` в текущем каталоге. Другой файл можно
передать аргументом скрипту:

```sh
./run.sh --config путь/к/config.ini
```

Для обычного репозитория приложение загружает файл `APKINDEX.tar.gz` по URL
репозитория; можно указать URL самого `APKINDEX.tar.gz`. Индекс разбирается
непосредственно из архива стандартными средствами Python, без запуска `apk`
или использования сторонних библиотек.

В тестовом режиме `repository` указывает на текстовый файл графа в формате
списка смежности. Каждая непустая строка имеет вид
`ПАКЕТ: ЗАВИСИМОСТЬ1 ЗАВИСИМОСТЬ2`; пакет и зависимости состоят из больших
латинских букв. Строки, начинающиеся с `#`, и комментарии после `#`
игнорируются. Например:

```text
A: B C
B: D
C: D E
D: C
E:
```

Для воспроизведения примера используйте готовые файлы:

```sh
./run.sh --config examples/test_config.ini
```

Результат включает транзитивные рёбра, в том числе цикл:

```text
Граф зависимостей A:
A -> B, C
B -> D
D -> C
C -> D, E
E -> (нет)
```

Будут выведены все пакеты, достижимые из `A`. В примере есть ромб зависимостей
`A -> B/C -> D` и цикл `C -> D -> C`; цикл не приводит к бесконечной рекурсии.
Пакет `F` из `examples/test_repository.txt` не выводится, так как он не достижим
из `A`. Для проверки пакета без зависимостей замените в тестовой конфигурации
`package_name = A` на `package_name = E`. Версия в тестовом режиме не
используется.

Для APK-репозитория корень выбирается по точному совпадению имени (`P`) и
версии (`V`), а зависимости берутся из поля `D`. Граф обходится DFS с
рекурсией; каждая вершина раскрывается только один раз, поэтому циклические
зависимости безопасны. Зависимость, совпадающая с единственным `p`-полем
пакета-поставщика, связывается с этим пакетом для продолжения обхода.
Вершина без зависимостей отображается как `ПАКЕТ -> (нет)`. Изображение пока
не создается; параметр `output_file` будет использован при добавлении
визуализации. Ошибки конфигурации, репозитория и тестового графа выводятся в
stderr с кодами завершения `2`, `3` и `4` соответственно.

## Проверки

Тесты проверяют конфигурацию, получение и разбор APKINDEX, точное совпадение
версии, DFS для транзитивных зависимостей, ромба, циклов, недостижимых вершин,
обработку тестового формата и ошибки:

```sh
python -m unittest discover -s tests
```

# Этап 1. Минимальный прототип с конфигурацией

Реализовано минимальное CLI-приложение на стандартной библиотеке Python.
Получение зависимостей и генерация графа пока не выполняются: на этом этапе
приложение загружает настройки, проверяет их и выводит в формате
`ключ=значение`.

## Настройка

Параметры задаются в секции `[settings]` файла `config.ini`:

| Ключ | Назначение и проверка |
| --- | --- |
| `package_name` | Имя пакета; обязательное, без пробелов. |
| `repository` | При `test_mode = false` — полный HTTP(S) URL с хостом; при `true` — путь к существующему файлу тестового репозитория. |
| `test_mode` | Режим тестового репозитория: только `true` или `false`. |
| `version` | Версия пакета; обязательная, без пробелов. |
| `output_file` | Имя файла изображения; поддерживаются расширения `.png` и `.svg`, путь к каталогу указывать нельзя. |

Пример готовой конфигурации находится в `config.ini`.

## Запуск

Запустить из корня проекта:

```sh
./run.sh
```

Скрипт запускает приложение с `python3` из корня проекта, поэтому его можно
вызвать и из другого текущего каталога.

По умолчанию читается `config.ini` в текущем каталоге. Другой файл можно
передать аргументом скрипту:

```sh
./run.sh --config путь/к/config.ini
```

При успешной проверке в stdout выводятся все пять параметров в формате
`ключ=значение`. При ошибке приложение выводит понятное сообщение в stderr
и завершает работу с кодом `2`. Ошибки значений параметров перечисляются
совместно; отсутствующие ключи также явно указываются.

## Проверки

Тесты проверяют корректную загрузку настроек, тестовый файл репозитория,
некорректные и отсутствующие значения всех параметров, вывод CLI и обработку
ошибки чтения конфигурации:

```sh
python -m unittest discover -s tests
```
